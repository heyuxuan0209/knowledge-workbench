一句话核心AI 智能体在企业落地的瓶颈不是模型不够强，而是组织内部的上下文没有对 AI 开放；打造 AI 原生组织的本质，是把会议室、聊天记录、文档这些"暗数据"变成 agent readable，让沟通成为 prompt，让执行在沟通中自然发生。
讲述脉络
开场定调：表现不好，大概率不是模型的问题

Zara 开场点出一个她在创业者、CEO 和开发者中间反复观察到的现象：今天海外的模型、中国的模型都已经非常强了，强到足以完成企业日常办公场景下的大部分任务。如果一个 AI 智能体落地效果不好，"大概率不是它的问题，是你的问题"——是上下文没有给够。这个判断把她整场分享的基调定在了一个反常识的位置上：先别急着换模型，先从自己身上找原因，你给它的信息够不够全、够不够多。

核心定义：AI 原生 = agent readable

接下来的论述围绕一个可操作的等价替换展开。她说，说到"AI 原生组织"的时候，你可以把它替换成另一个词——agent readable。意思是，企业里各种信息对于智能体是不是可见的、可读的。会议记录、沟通痕迹、决策流程这些东西如果智能体看不到，它就缺少上下文，表现一定差。因此，她要讲的五个落地实践——AI 原生会议、数据分析、招聘、团队级别智能体、组织内 AI 学习氛围——本质上都在回答同一个问题：怎么把整个公司变成 agent readable 的系统？

五个落地实践，逐层展开

第一个实践是 AI 原生会议，三个递进等级。Level 1 是多数人已在做的：开会用 AI 做纪要、提炼待办，已普及但只是基础。Level 2 是会后智能体不仅总结，还自己把待办办了——会议的结束变成工作的开始（销售开完会 CRM 自动更新，产研开完会项目系统自动下发、bug 自动修）。她用自己的工作流举例：开完会智能体自动获取会议记录，先生成个性化摘要，再提炼"我需要做的待办"和"你可以干的待办"两个清单，她点名"你做一、你做二"，对方就去执行。Level 3 更激进——智能体直接入会、边听边干（当时正在灰度，她称"非常神奇"）。真实客户拜访场景：客户在会上分享反馈，以前要等会后再总结分发，现在她在会上直接说"刚才客户对这个产品有什么反馈，你总结一下"，智能体根据实时逐字稿马上在飞书消息里完成。还能会上现场拉数、参与 brainstorm。她把价值提炼为一句：压缩沟通和执行之间的距离，做到"沟通即执行"。由此引出工作方式三次演化：打字式→口喷式→聊天式。

在这个推进中她插入了对 prompt 的根本反思：过去觉得 prompt 是一段精心撰写的长文字，现在可以重想——把智能体拉进群，聊天记录就是它的 PRD；拉进会议，逐字稿就是它的 prompt；它甚至读到日历里明天的客户拜访，主动去 CRM 查信息、备材料。前提是你把这些信息都对它变成可读的。原话"那个会议里的逐字稿就是他的 prompt…当 agent 感知到了你在飞书里的各种信息，它就可以主动地去完成各种事情"

第二个实践是 AI 原生数据分析，重音落在"归因"的突破。先建议把 Excel 发给智能体做成可交互 HTML（可拖参数的沙盘/报价器，右边实时联动），不是静态图表。更本质的是归因——为什么涨跌需要大量业务上下文，而这些往往不在任何看板里。数据分析师的解法：让智能体每天扫飞书消息/文档/会议更新一张"业务动作表"，分析时参照它。比如某天数据突然跌了，智能体能追溯到"投放停了"——而这条信息只在某个群的某条消息里。当所有信息 agent readable，点就连成了线。

第三个实践是招聘。用 AI 筛人：让智能体扫你和下属的一对一/会议记录，提炼你常用的反馈类型、倒推人才画像、自动生成 JD/筛选标准/面试题。筛 AI native 的人：两轮面试法——第一轮禁用 AI 看基础素质，第二轮只能用 AI 给一个"不用 AI 完不成"的任务并保留全部聊天记录，重点看人与 AI 互动的过程，判断他是否真会驾驭 AI。

第四个实践是团队级别智能体，从"个人助理"走向"共享同事"。她把用 AI 分三段位：人跟人（无 AI）→ 每人跟自己的 AI（割裂、彼此不知道对方在用 AI 做什么）→ AI 无缝融入人与人协作。多数人卡在第二段。她以 Anthropic 的 Claude Tag 为例说明趋势。团队智能体能做而个人做不到的：工作接力（同一界面里下游直接接着做、纠偏）、潜移默化培训（看同事怎么用、"原来还能这么用"）、参与 brainstorm（一起产出 prompt）、全局视角（跨群跨文档写周报/推进项目）。她还点出：组织低效常来自上下游依赖等待，团队智能体服务上下游能让跨部门需求内部闭环。

最后一个实践是学习氛围，几条反传统建议：干中学、玩中学（先干后学，做出来再问智能体原理，让学 AI 变轻松）；利用团队智能体的潜移默化（引 Shopify——智能体只在群聊工作、不私聊，形成"渗透式学习"，所有人向所有人学）；刻意创造懂 AI 与懂业务两类人的互动场域（内部活动、内部 FDE 驻扎业务部门）；特别推荐全员装机活动——很多非技术部门的最大障碍不是不会用，而是装不上，现场一两小时装好，后面就是聊天的事。

现场演示（晶晶）：把 Level 3 演成活的

紧接 Zara 的框架，飞书产品经理晶晶做了一场 live demo——不带 PPT，只把自己的智能体拉进会议。她和 Zara 就"要招一个 AI native 运营"正常地聊，智能体在背后边听边把五件事干了：口头聊完岗位画像后一句"帮我写份标准 JD 发会议弹幕"，一分钟出稿、"改改就能用"；现场查华东 7 月销售总额、全国销量最高单品；把全国销售数据做成 HTML 数据看板；围绕"为什么要团队级 agent"边听讨论边实时画 HTML slide；最后用瑞幸 CLI 买了杯抹茶拿铁送到会场。她顺带分享自己团队的团队智能体"CC 王"——进所有项目群和会议、有全部上下文，会主动 at 那个"说要上线却忘了同步"的研发。落地两条路：aily 的"团队智能伙伴"，或走 Claude Code / Codex Bridge 团队模式把海外最强模型拉进群；她个人做法是让智能体每天扫各群前一天的聊天/文档/会议自更新知识库，"每天都比前一天更懂我们"。收尾金句：你和同事喝着咖啡聊着天，活 agent 在背后干完了——人应该 focus 在创意的沟通、表达和 brainstorm，执行交给 agent。

结尾的感想：没有标准答案，让结果自己长出来

收束时她给出三个带规劝意味的感想。第一，AI 原生组织没有标准答案，硅谷最领先的组织也没有，方向太新、每个组织业态与文化各异，指望抄模板不现实，只能自己大胆实验。第二，AI 落地的场景不是规划出来的，是长出来的——变化太快没法从终局倒推，只能在敢探索的文化里让它自然生长。第三，不能急于求成：她引用生产力 J 型曲线——每次技术革命短期反而带来一定效率下降（学习、磨合、改造流程都要成本），但长期一定有巨大提升。"实践是打造 AI 原生组织的唯一方法"，是她最后留下的一句话。

关键案例与细节

· 会议三成熟度模型：L1 纪要+待办；L2 会后自动执行（销售更新 CRM、产研更新项目系统）；L3 入会边聊边办——客户还在说话，反馈总结已发到飞书消息。
· 可交互 HTML 数据分析：Excel→可拖参数的交互网页（预算沙盘、报价器）。
· "业务动作表"归因：智能体每天扫飞书信息生成业务动作日志，解决"跌了因为投放停了、但这事不在任何 Dashboard 里"的信息断层。
· 两轮面试法：先禁 AI 看素质、再只能用 AI 看"驾驭过程"。
· 全员装机活动 / Shopify 渗透式学习（只群聊不私聊，所有人向所有人学）。

值得记住的表述
"Today's models are already very strong. If an agent's performance is poor, most likely it's not the model's problem — it's your problem, it's a context problem."今天的模型都已经非常强了，如果智能体表现不好，大概率不是它的问题，是你的问题——是上下文的问题。
"The end of a meeting is the beginning of work."会议的结束是工作的开始。

暗数据结构化：工作台做一个类"业务动作表"的模块，让 AI 定期扫项目群/纪要/文档更新日志，自动生成时间线版上下文，作为归因与提醒的基础层——"把点连成线"的工程化。
"沟通即 prompt"用于中英双线：选题讨论/编辑会/反馈全对 AI 开放，沟通过程本身就是 brief，不用专门下游写。可试点"AI 入会+自动执行"的创作工作流。
装机 vs onboarding：Zara 说很多人卡在"装机"。工作台是否也有一个非技术用户永远跨不过的阻塞点？设计一个极简"上手工坊"，第一次就跑通最小闭环。
归因当差异化切入：归因是所有 Dashboard 工具回避的难题。建立在"AI 可读所有非结构化沟通数据"之上，可能是工作台和市面 BI 拉开差距的独特切入。
