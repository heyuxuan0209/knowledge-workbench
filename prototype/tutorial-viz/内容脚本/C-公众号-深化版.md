# 《AI 早就够强了，是我们把它拴住了》
> 用途：公众号 / 知识区长口播（约 2.5 分钟）· 本人口吻·平实·内容加深
> 引用：Anthropic 团队成员 Tarik Shaupar 关于新一代模型的分享

所有人都在学，怎么把提示词写得更好。
我做产品做了大半年，越来越怀疑：这个方向，可能一开始就错了。

我描述一个按钮怎么摆，改来改去，一整天就过去了。
后来我换了种说法：别写，先做几个能点的 html mock，我来选。
三下点击就定了。
这大半年七八个产品，几乎每个关键决定，都是这么定的。

一开始我以为，这只是个沟通技巧。想久了才发现，不是。
跟 AI 干活，真正卡住你的，从来不是它笨。
是你给它套的那根缰绳——而那根缰绳，恰恰是你以为的"专业"：把需求说清楚。

你想过没有，我们为什么这么信"说清楚"？
因为在过去，把东西真做出来太贵了——要工程师、要排期、要时间。做一版试错的成本很高，所以最划算的办法，是先在纸上、在文档里把它描述清楚，争取一次做对。
"把需求说清楚"，是那个时代最聪明的技能。
可现在，AI 让"做出来"几乎不要钱。成本一反过来，游戏就反了：不再是先说清楚、再做对，而是先做个粗的、直接上手改。

而且这里有个很关键的地方：让它"做出来"的那个东西，是 html。
你可能会说，交互原型不是早就有吗——Figma、Axure，早就能做能点的。
没错。但问题一直是：做一个真能交互的原型，很费时间。给每个还没想清楚的方案都做一版可交互的，成本太高、性价比太低。所以过去大多数时候，我们宁可先把需求描述清楚、直接开发，赌它一次做对，赌输了再返工。
现在这笔账被彻底改写了。html 天生就是大模型最擅长的语言——满世界的网页都是 html，它张口就来，而 html 本来就能真交互。所以让 AI 一次甩几个能点的 html mock，又快又便宜，几乎零成本。
于是"先做个能点的、直接上手挑"，第一次比"描述—盲开发—返工"更划算。它省下的，正是那些本来会浪费在盲目开发和返工上的时间。

后来我看到 Anthropic 团队成员 Tarik Shaupar 的一个分享，他把这件事推得更远。
他说，模型是"养"出来的，不是"设计"出来的。它的潜力，早就超过了我们用它的方式。真正给它套上缰绳的，是我们自己——那些越写越长的指令、越描越细的规格书。你写得越死，它能发挥的空间就越小。
他还有句话我印象很深："地图不等于领土。"
你的计划是地图，真实的问题是领土。它越强，能走的领土越大，你不知道的也就越多。
所以更值钱的用法，根本不是让它执行你的指令，是让它帮你发现你自己没看到的地方——让它扫一遍你没注意的坑，让它反过来问你、专挑那些会改方向的问题，让它一次给你几个 html mock，把你自己都说不清的偏好摆出来。
我那句"做几个 html mock 我选"，其实只是这里面最小的一个动作。

所以"会用 AI"这件事，得重新定义了。
不是会把话说清楚——那是"东西很贵"时代的技能。
是知道往哪儿探、敢放手、认得出什么是好东西。
说句可能得罪人的：提示词工程被高估了。你越是把它当核心能力练，越是在打磨那根缰绳。

当然，也别走极端。想清楚的、只有一种做法的，直接让它写就行——html mock 是留给那些"还没成形"的方案的。
而且，这不是说 AI 什么都能干了。Tarik 那场分享里我最喜欢一句话："搭东西变容易了，但创造价值仍然很难。"
变便宜的，只是把东西做出来。真正稀缺的，还是判断、品味、知道什么值得做。

他还说，他回到几年前自己的老项目，过去要几周的功能，现在几个小时就好了。他挺高兴，但也有点失落。最后他说，回不去了，只能往前。
我大概能理解这种感觉。

所以别再纠结，怎么把话对 AI 说得更漂亮了。
把那根缰绳松开——去走你自己的地图，让它带你看看，那些你还不知道的东西。
